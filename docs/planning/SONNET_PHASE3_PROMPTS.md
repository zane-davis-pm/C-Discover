# Phase 3 — Sonnet Task Prompts (Part A & Part B)

Phase 3 of `PROJECT_PLAN_MULTISTATE.md` split into two evenly-sized tasks with a precisely defined interface between them, so they can be built and reviewed independently.

- **Part A — App side:** state-agnostic schema/types, namespaced data layout + loaders, state selector + routing. Ends with the app fully working for Florida under the new multi-state structure (data moved by a one-off script, pipeline untouched).
- **Part B — Pipeline side:** core-vs-adapter pipeline restructure, schema-driven hard-fail validation, Florida migrated as the first adapter state, verified against the golden snapshot.

**Run Part A first.** Part B regenerates data into the layout Part A defines. The shared contract (§Interface below) is embedded in both prompts — do not let either task deviate from it.

---

## Shared interface contract (embedded in both prompts)

1. **Data layout:** `/public/data/{state}/` where `{state}` is lowercase USPS code (`fl`). All current flat files move under it, including `deep-dive/`. Example: `/public/data/fl/counties.json`.
2. **Manifest:** `/public/data/states.json`:
   ```json
   {
     "states": [
       {
         "code": "fl",
         "name": "Florida",
         "entity_types": ["county", "municipality", "school_district", "special_district"],
         "map": { "center": [27.8, -83.7], "zoom": 7 },
         "regions": ["Northwest", "..."]
       }
     ]
   }
   ```
   `entity_types` drives which tabs/views render per state (special districts are state-optional per Phase 0). `map` and `regions` replace any hardcoded Florida constants.
3. **Routing:** path prefix — `/{state}/explore`, `/{state}/map`, `/{state}/compare`, `/{state}/shortlist`, `/{state}/workspaces`. Legacy prefix-less routes redirect to `/fl/...` (Florida default) preserving query params. The `/entity/[type]/[id]` bookmark redirect gains the state prefix in its target.
4. **Schema changes to `lib/types.ts`:** every entity gains `state: string` (USPS code) and `wyn_url: string | null` (placeholder — **never rendered** until D6 resolves). `entity_subtype` union for municipalities extends with `"township"`. `total_revenue` stays universal-but-nullable; add `data_gaps?: Record<string, "unknown" | "unavailable" | "not_applicable">` if not already present in equivalent form.
5. **Snapshot rule:** Florida entity data regenerated by Part B must match the committed data Part A moved — same values, new location. `check_snapshot.js` must be updated (Part A) to diff the new paths, and must pass (Part B).

**Task: Phase 3 Part B — restructure the data pipeline into shared core vs. per-state adapters, with Florida as the first adapter state, verified against the golden snapshot. The app/UI is OUT OF SCOPE; do not modify `lib/`, `app/`, or `components/`.**

Target architecture:

```
scripts/pipeline/
  core/                  # state-agnostic
    fetch_census_acs.js  # parameterized by state FIPS; from 03/03b
    fetch_geo.js         # TIGER/Line or state config-driven; from 01/02
    build_entities.js    # consumes intermediate format; from 09-12
    validate.js          # schema-driven, hard-fail; from 13
    build_deep_dive.js   # from 21 (includes Phase 2 benchmark computation)
    lib/                 # shared helpers, intermediate-format schema
  states/
    fl/
      config.js          # FIPS, source URLs, entity types, region defs
      adapters/          # EDR/FLDOE/FloridaCommerce fetchers; from 04-08
      contacts/          # from 14/15 (contact application is FL-specific seed data)
      seeds/
  run_all.sh             # --state fl | --all
```

Work in this order:

**B1 — Intermediate format + core extraction.** Define a documented intermediate format (JSON schema or typedef in `core/lib/`) that state adapters emit and core builders consume: per entity type, the state-specific fiscal/registry fields keyed by a stable join key (FIPS/district number). Extract the state-agnostic scripts into `core/`, parameterized by state config. The Census fetcher takes state FIPS from config; the silent-fallback behavior on missing `CENSUS_API_KEY` documented in `run_all.sh` becomes a **hard failure** (exit non-zero, clear message naming the missing key).

**B2 — Florida adapter.** Move EDR/FLDOE/FloridaCommerce/special-district fetchers (04–08) and contact application (14/15) into `states/fl/`, emitting the intermediate format. `states/fl/config.js` carries everything Florida-specific: source URLs, FIPS, entity types (all four), region definitions matching `public/data/fl/`'s existing values, benchmark config. Nothing in `core/` may reference Florida, EDR, or FLDOE — enforce by grep.

**B3 — Schema-driven validation, hard-fail.** Rewrite validation so it checks every output file against a declared schema: required universal fields (population, median_hh_income, total_revenue-nullable, state, wyn_url, name, website, geo refs), per-state optional fields from state config, row counts within configured bounds (e.g., FL counties == 67), and `data_gaps` entries wherever a nullable universal is null. Any violation exits non-zero **naming the file, field, and entity id**. This is the loud-failure requirement from Phase 5's design — silent partial data already caused one incident (see the warning block in the old `run_all.sh`).

**B4 — Orchestration + snapshot gate.** `run_all.sh --state fl` (and `--all` over the manifest) runs: state adapters → core fetch → build → validate → deep-dive/benchmarks → write to `/public/data/{state}/` + update `states.json` metadata and `metadata.json` per state. Then regenerate Florida end-to-end and run `node scripts/pipeline/check_snapshot.js`. **The regenerated output must match committed data exactly** (the snapshot script's documented tolerance rules aside). This is the merge gate: if values drift, find the rewired logic and fix it — do not adjust the snapshot or the tolerances to make it pass, and do not commit regenerated data that fails the gate. If a drift is truly explainable (e.g., a source published new data between runs), stop and report it to me instead of deciding yourself.

**Definition of done — all must pass, show me the output:**
1. `bash scripts/pipeline/run_all.sh --state fl` completes cleanly from scratch.
2. `node scripts/pipeline/check_snapshot.js` passes on the regenerated output.

4. Unsetting `CENSUS_API_KEY` makes the run **fail loudly** (demonstrate: run with the key unset, show the non-zero exit and message).
5. Deliberately corrupt one field in an intermediate file (temporarily) and show validation failing with file/field/entity-id named; then restore.
6. `npm run build` still clean (no app changes, but prove nothing broke).
7. Update `AGENTS.md`: pipeline architecture (core/adapters/intermediate format), how to run per-state, the hard-fail contract. Add `docs/ONBOARDING_A_STATE.md` skeleton: the step-by-step for adding a state (config + adapters + seeds + validation bounds), citing the Florida adapter as the reference implementation — full doc is Phase 6, but the skeleton captures the contract while it's fresh.
